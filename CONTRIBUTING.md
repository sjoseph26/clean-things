# Contributing to v0.6.0

Use a branch for each issue. State the observed problem, affected requirement, proposed change and test evidence in the pull request. Run `npm run check`, `npm test` and the browser suite for changed UI behaviour. Do not commit configuration generated for a live project, signing keys, customer data, participant identities or credentials.

Have another member review changes before merging. Each member should use their own Git identity and record their actual work in [the contribution record](docs/CONTRIBUTIONS.md). The initial repository import is not historical evidence of who authored earlier releases. Do not backdate commits or split AI-generated work into fabricated member contributions.

For deployment, complete the [release gates](docs/RELEASE-STATUS.md). GitHub Actions builds a fictional QA app; it never changes the live database or publishes a live APK.
